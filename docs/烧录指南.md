# 立创·实战派 ESP32-S3 — 固件烧录说明

> 目标板：立创·实战派 ESP32-S3（WROOM-1-N16R8，16MB Flash + 8MB Octal PSRAM）
> 依据：立创官方 wiki + 本机实测

---

## 1. 先搞懂板上的 USB 拓扑（这是所有烧录问题的根源）

板载 **CH334F 是一颗 4 口 USB 集线器**，Type-C 是它的上行口：

```
[PC USB] ──> CH334F HUB 上行口
                 ├─ 下行 D4 ──> CH340K ──> ESP32-S3 的 UART0   ← 带自动下载电路
                 └─ 下行 D3 ──> ESP32-S3 原生 USB-OTG          ← 无自动下载电路
```

官方 wiki 原话：

> 「USB 转串口芯片使用 CH340K……可以**实现自动程序下载**和串口终端调试功能。」
> 「**因为 BOOT 和 RESET 已经被自动下载电路控制，所以这里的 BOOT 按键其实就是个用户按键了**。」<br>
> 「IO46 引脚，在下载模式，必须是低电平，否则无法下载程序（板上有下拉电阻）。」

**由此得出的两条硬规则：**

| # | 规则 | 原因 |
|---|---|---|
| 1 | **优先用 CH340K 那个串口烧录**（本机当前为 COM8） | 只有这条路有 DTR/RTS → EN/BOOT 自动下载电路 |
| 2 | **不要试图手动按 BOOT 进下载模式** | 板上 BOOT 键已被改造成用户键，按它没用 |

## 2. 三种烧录方式（按推荐度排序）

### 方式 A：esptool 走 CH340K —— 推荐

```bat
D:\Espressif\python_env\Scripts\esptool.exe --chip esp32s3 -p COM8 -b 460800 ^
  write_flash 0x0 "G:\workbuddy\语音助手\dist\elder-companion.bin"
```

esptool 会通过 DTR/RTS 自动把芯片拉进 ROM 下载模式，**不需要按任何按键**。
若握手失败，先降速到 `115200` 重试一次。

### 方式 B：乐鑫官方 Flash Download Tool（图形界面，最省心）

1. 下载 <https://www.espressif.com.cn/en/support/download/other-tools>（Flash Download Tool）
2. 选 `chipType = ESP32-S3`，`workMode = develop`
3. 只填**一行**（用合并后的单 bin）：

   | 地址 | 文件 |
   | --- | --- |
   | `0x0` | `elder-companion.bin` |

4. `SPI SPEED = 80MHz`、`SPI MODE = DIO`、`FLASH SIZE = 16MB`，COM 选 CH340K 那个口
5. 点 `START`

### 方式 C：走板载 USB-JTAG（OpenOCD）—— 完全绕开串口

只有在前两种都不通时才用。WinUSB 驱动需要先被 Zadig 绑定到 `USB\VID_303A&PID_1001&MI_02`。

```bat
D:\Espressif\tools\openocd-esp32\v0.12.0-esp32-20250707\openocd-esp32\bin\openocd.exe ^
  -s D:\Espressif\tools\openocd-esp32\v0.12.0-esp32-20250707\openocd-esp32\share\openocd\scripts ^
  -f board/esp32s3-builtin.cfg ^
  -c "program_esp build/elder-companion.bin 0x10000 verify exit"
```

## 3. 常见失败与处理

| 现象 | 真实原因 | 处理 |
| --- | --- | --- |
| `A serial exception error occurred: Write timeout` | 芯片没进下载模式，App 占着 CDC 且不消费 OUT 端点 → `usbser.sys` 缓冲填满 | 换 CH340K 那个口（方式 A）；或拔插 USB |
| `Wrong boot mode detected (0xXX)!` | 同上 | 同上 |
| `Could not open COMx` | 端口号变了 / 设备被拔 | 重新枚举端口（见第 4 节） |
| `Failed to set baud rate 115200` | CH340 驱动异常或端口被占 | 换口；重插；任务管理器杀掉占用进程 |
| 集线器报 **Code 43 `CM_PROB_FAILED_POST_START`** | HUB 过流保护或线缆问题 | 换一根**数据线**、换一个**主板原生 USB 口**（别走显示器/键盘 Hub） |
| `Invalid head of packet (0x45)` | 收到的是 App 日志而不是 bootloader 应答 | 让 esptool 自己复位（默认行为），别用 `--before no_reset` |

## 4. 快速查当前端口号

```bat
:: 列出所有串口及其设备路径
reg query HKLM\HARDWARE\DEVICEMAP\SERIALCOMM
```

或用 PowerShell：

```powershell
Get-PnpDevice -PresentOnly | Where-Object { $_.FriendlyName -match 'COM\d+' } |
  Select-Object FriendlyName, Status, InstanceId
```

识别规则：
- **`VID_303A&PID_1001`** = ESP32-S3 原生 USB（COM 口，无自动下载）
- **`VID_1A86&PID_7522`** = CH340K = **烧录用这个**

## 5. 生成一个合并的固件镜像

### 5.0 ⚠️ 打包前必做：清干净 build 目录

```bat
rmdir /s /q G:\workbuddy\语音助手\firmware\xiaozhi\build
```

**为什么这条不能省**：`firmware/xiaozhi/build/config/sdkconfig.h` 是**未入库的本地构建产物**
（`sdkconfig` 被 gitignore）。里面的 `CONFIG_OTA_URL` 可能仍是上游第三方的地址。
不清就重新构建，打出来的设备会去连**别人的服务器**——症状是设备能启动、能连网，
但语音链路永远不通，而固件日志里看不出异常。

固件的真源配置在 `Kconfig.projbuild`，`CONFIG_OTA_URL` 默认已指向自己的
`/api/voice/ota`。**但真源改了不代表 build 里的产物跟着变**，所以必须删目录重编。

> 关联：`idf.py build` **不读**板级 `config.json`；驱动是否编进去以 `SDKCONFIG_OVERLAY`
> 为准。改配置后没清 build 目录，是本项目踩过的「改了但没生效」的典型来源。

### 5.1 【推荐】从 GitHub 下载已构建好的镜像

固件由 GitHub Actions 在 Espressif 官方容器里编译（本地不装 IDF 也能拿到成品）：

1. 打开仓库的 **Actions → firmware-build**，选最新一次 **绿色**的运行
2. 页面底部 **Artifacts** → 下载 `elder-firmware-esp32s3`（是个 zip，约 2.5 MB，解压后 6 个文件）
3. 解压出来**只需要烧这一个**：

   ```
   elder-firmware-esp32s3-merged-flash.bin
   ```

   从 `0x0` 直烧，命令：

   ```bat
   python -m esptool --chip esp32s3 --port COM3 write_flash 0x0 elder-firmware-esp32s3-merged-flash.bin
   ```

   > 该次运行的 job summary 里列出了每个文件的字节数和 SHA256 前 16 位，
   > 可以用它确认自己下对了文件。

其余 5 个文件（`bootloader.bin` / `partition-table.bin` / `ota_data_initial.bin` /
`xiaozhi.bin` / `generated_assets.bin`）是按 `flasher_args.json` 分地址烧写的**备选**，
日常不用管。`flasher_args.json` 里已经写好了每个文件该写到哪个地址，
用乐鑫 Flash Download Tool 时照它填即可。

> ⚠️ 早期版本的 CI 有一个 bug：`merge-bin` 因路径写错而失败，但被 `|| echo warning`
> 吞掉了，于是 job 显示绿色、summary 让下载一个**从未生成过的文件**。
> 已修（commit `05c70e3`）。如果你下载的 artifact 里**没有** merged 那个文件，
> 说明拿到的是旧构建 —— 回 Actions 里看该次运行的日志，确认 `merged-flash.bin = N 字节`
> 那一行存在再烧。

### 5.2 本地自行合并（本机装了 ESP-IDF 时）

```bat
python G:\workbuddy\语音助手\tools\make_firmware.py
```

输出：`G:\workbuddy\语音助手\dist\elder-companion.bin`
脚本会同时打印好完整的烧录命令。

## 6. 外部设备扩展（IO 分配与硬件要求）

> 本节的 IO 编号**不是抄 ESP32-S3 通用规格**，而是逐条读
> `firmware/xiaozhi/main/boards/lichuang-dev/config.h` 与
> `lichuang_dev_board.cc` 取出的**当前固件实际占用**情况。
> 改固件前请先核对该文件。

### 6.1 IO 已被本固件占用的部分（**不要接外部设备**）

| 功能 | IO | 备注 |
|---|---|---|
| I2S 音频 MCLK | 38 | 音频 |
| I2S WS | 13 | 音频 |
| I2S BCLK | 14 | 音频 |
| I2S 数据入 | 12 | 麦克风 |
| I2S 数据出 | 45 | 扬声器 |
| 音频 I2C SDA | 1 | PCA9557 / FT5x06 / ES8311 共用 |
| 音频 I2C SCL | 2 | 同上 |
| 背光 | 42 | ST7789 |
| 板载 LED | 48 | |
| **BOOT 键（用户键）** | **0** | ★ 见 6.3，这是唯一可用作输入的按键 |
| SPI MOSI（屏） | 40 | ST7789 |
| SPI SCLK（屏） | 41 | ST7789 |

**I2C 总线上已挂的器件**（都在 IO1/IO2 这条总线上，不要再加冲突器件）：

| 器件 | 地址 | 用途 |
|---|---|---|
| PCA9557 | `0x19` | IO 扩展器（音频编解码器控制、摄像头供电） |
| FT5x06 | `0x38`（标准） | 电容触摸 |
| ES8311 | 0x18 类 | 音频 Codec |

### 6.2 摄像头占了 15 个 IO（★ 已改为「探到硬件才初始化」）

| 功能 | IO | | 功能 | IO |
|---|---|---|---|---|
| XCLK | 5 | | D4 | 15 |
| SIOD | 1 | | D3 | 17 |
| SIOC | 2 | | D2 | 8 |
| D0 | 16 | | D1 | 18 |
| D6 | 4 | | D7 | 9 |
| D5 | 6 | | VSYNC | 3 |
| HREF | 46 | | PCLK | 7 |

⚠️ **重要事实（已变更）**：`lichuang_dev_board.cc` 里 `InitializeCamera()`
**仍然在构造流程里被调用**，但它**内部现在会先探测硬件**：

- 摄像头驱动已真正编进固件（此前是「代码在、驱动没编进去」，等于白占 IO 却出不了图）；
- 探测不到硬件时**提前返回**，并把 `camera_ = nullptr`
  （成员变量已用 `nullptr` 初始化，见 `lichuang_dev_board.cc:77-81`
  —— 不初始化的话 `GetCamera()` 会返回野指针）；
- 下游 `mcp_server.cc` 靠 `if (camera)` 决定是否注册 `take_photo` 工具，
  所以探不到摄像头时该工具**不会注册**，不会给出一个必然失败的接口。

⇒ **无摄像头机型上这些 IO 在运行时不会被实际驱动**，但仍按「已占用」保守规划。

其中 **11 个是摄像头独占**（关掉摄像头即可全部腾出）：
`3, 4, 5, 6, 7, 8, 9, 15, 16, 17, 18`
（分别是 VSYNC / D6 / XCLK / D5 / PCLK / D2 / D7 / D4 / D0 / D3 / D1）

另外 `1, 2`（SIOD/SIOC）是**与音频 I2C 总线共用**的，关摄像头也腾不出来。

⇒ **若要接外部设备，第一优先仍是把摄像头关掉**，一次腾出 11 个 IO。
做法：把板级真源配置里的 `CONFIG_CAMERA_GC0308=y` 去掉。
⚠️ **注意**：`idf.py build` **不读** `config.json`；驱动必须经 `SDKCONFIG_OVERLAY` 真源启用，
而 `sdkconfig` 是构建产物且被 gitignore。只改 `config.json` 不改 overlay 是**不生效**的。
★ 本项目尚未做关闭摄像头的改动 —— 下面 6.3 给的是**当前状态**下可用的 IO。

### 6.3 当前状态下，**可用**的 IO（接外部设备看这张表）

ESP32-S3 的 GPIO 必须在 `0-21` 和 `26-48` 两个区间内（`22-25` 为 SPI Flash/PSRAM
占用，**绝对不可用**）。

当前固件共占用 24 个 GPIO，**剩余 21 个空闲**：

| IO | 建议用途 |
|---|---|
| **0** | ★ 外部按键输入（唯一已接按键，即板载 BOOT 键） |
| 10, 11 | 通用 GPIO / 中断 |
| 19, 20 | 通用 GPIO |
| 21 | 通用 GPIO（注意：21 常作 USB D-，若用原生 USB 则被占） |
| 26, 27, 28 | 通用 GPIO |
| **29, 30, 31, 32** | 通用 GPIO |
| 33-37, 39 | 通用 GPIO（38 已占；39 常作 MCLK 备用） |
| 43, 44 | 通用 GPIO |
| 47 | 通用 GPIO |
| 46 | ⚠️ 下载模式下必须为低电平（板上有下拉），已被摄像头 HREF 占 |

> `46` 在下载模式被板载下拉电阻拉低，官方 wiki 明确写了这一点，
> **不要在 IO46 上接需要高电平才能工作的外设**。

### 6.4 外接硬件的要求

**逻辑电平**：ESP32-S3 是 **3.3V 逻辑**。5V 器件必须经电平转换（如 TXS0108E）。

**供电**：
- 板载 3.3V 走 LDO，能带动的电流有限；
- 大电流器件（舵机、继电器、振动马达、灯带）**必须外部独立供电**，
  且**必须与板子共地（GND 必须相连）**，否则信号没有参考电平。
- 建议：外接电源经一个 **100Ω~1kΩ 电阻 + 共地**接入，电源走线不要与 I2S 音频线并走
  （音频底噪的主要来源就是电源串扰）。

**外接传感器建议选型**：

| 用途 | 推荐 | 接哪个 IO | 说明 |
|---|---|---|---|
| 跌倒/离开检测 | BMA400 或 MPU6050 | SDA→1、SCL→2 | ★ **共用现有 I2C 总线**，需确认地址不冲突 |
| 药盒开合 | 微动开关 + 上拉 | 任意空闲 GPIO | 一根线接地即可 |
| 紧急呼叫 | 大按钮 | **IO0** | 与板载 BOOT 键并联，程序里要能区分 |
| 指示灯 | LED + 限流电阻 | 任意空闲 GPIO | 串联 330Ω~1kΩ |

**I2C 注意**：本板 I2C 已挂 3 个器件。新增 I2C 器件前查清地址
（BMA400=0x68、MPU6050=0x68，**两者地址相同，不能同时接**）。

### 6.5 要接的东西需要改固件吗

| 外设 | 是否要改固件 |
|---|---|
| 按键（IO0 / 任意 GPIO） | **要**。在 `elder_input.c` 里注册为确认动作 |
| 药盒开关等简单 GPIO | **要**。同上 |
| 挂在现有 I2C 上的传感器 | **要**。新增驱动，且要处理与 PCA9557/FT5x06 共总线 |
| 摄像头（若要真正启用） | 已初始化好了，但本项目未使用 |

> 固件侧按确认的现有路径：断网时老人用**长按 → 30 秒内短按**确认服药。
> 新增的外部按键应接到同一条确认路径上，详见 `docs/决策记录.md` D11。

## 6.6 首次使用：配 WiFi（不需要 APP）

固件**原生支持浏览器配网**，不需要装任何 APP：

1. 设备上电后，它会自开一个 WiFi 热点
2. 屏显热点名（形如 `XiaoZhi-XXXX`，取 MAC 后两位）与配网页面地址
3. 用手机或电脑连上这个热点
4. 浏览器会**自动弹出配网页面**（DNS 强制门户拦截）
5. 页面在固件里：`firmware/xiaozhi/managed_components/78__esp-wifi-connect/assets/wifi_configuration.html`
6. 在页面上选 WiFi、输密码 → 提交，设备重启即联网

⚠️ **注意热点前缀是 `XiaoZhi-`（Z 大写）**，与上游项目的 `Xiaozhi-`（z 小写）
只差一个字母的大小写，肉眼极易看错。搜不到时先确认大小写。

> APP 只是这层浏览器配网的另一层封装，不是必需。

## 7. 分区表（xiaozhi v2.0.5 用的 16MB 布局）

> 本节是**当前 `partitions/v2/16m.csv` 的内容**。若已启用 MultiNet 离线语音识别，
> 分区表会被重排（新增 `model` 分区、缩小 `assets`），**以固件里的实际版本为准**。

| Name | Type | SubType | Offset | Size |
| --- | --- | --- | --- | --- |
| nvs | data | nvs | 0x9000 | 16K |
| otadata | data | ota | 0xd000 | 8K |
| phy_init | data | phy | 0xf000 | 4K |
| ota_0 | app | ota_0 | 0x20000 | 4032K |
| ota_1 | app | ota_1 | 0x410000 | 4032K |
| assets | data | spiffs | 0x800000 | 8M |

> 8MB 的 `assets` 分区用于放形象图 / 表情 / 字体 / 提示音 —— 需求 4（2D 卡通形象）
> 和 R4（离线提示音）的资源都落在这里，容量足够。

**nvs 只有 16K，但放得下离线提醒**：整张 `elder_rmd_table_t`（16 条提醒）是
**877 字节**，只占分区的 5.4%，剩下 15.2K 留给 settings / WiFi 等。
所以「提醒时间存本地」在容量上没有风险。

> ⚠️ 这 16MB 里 `assets` 独占 8MB（`0x800000` 起），两个 app 槽合计 7.9MB。
> 这是**esp-sr MultiNet 离线语音识别没能启用**的直接原因 ——
> 没有多余的分区放模型文件，而现有的 `ota_1` 槽已经被双 OTA 占着。
> 详见 `docs/决策记录.md` D11。
