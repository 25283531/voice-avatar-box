# 立创·实战派 ESP32-S3 — 固件烧录说明

> 目标板：立创·实战派 ESP32-S3（WROOM-1-N16R8，16MB Flash + 8MB Octal PSRAM）
> 依据：立创官方 wiki + 本机实测

---

## 1. 先搞懂板上的 USB 拓扑（这是所有烧录问题的根源）

板载 **CH334F 是一颗 4 口 USB 集线器**，Type-C 是它的上行口：

```
[PC USB] ──> CH334F HUB 上行口
                 ├─ 下行 D4 ──> CH340K ──> ESP32-S3 的 UART0   ← 带自动下载电路
                 └─ 下行 D3 ──> ESP32-S3 原生 USB-OTG          ← 无自动下载电路
```

官方 wiki 原话：

> 「USB 转串口芯片使用 CH340K……可以**实现自动程序下载**和串口终端调试功能。」
> 「**因为 BOOT 和 RESET 已经被自动下载电路控制，所以这里的 BOOT 按键其实就是个用户按键了**。」<br>
> 「IO46 引脚，在下载模式，必须是低电平，否则无法下载程序（板上有下拉电阻）。」

**由此得出的两条硬规则：**

| # | 规则 | 原因 |
|---|---|---|
| 1 | **优先用 CH340K 那个串口烧录**（本机当前为 COM8） | 只有这条路有 DTR/RTS → EN/BOOT 自动下载电路 |
| 2 | **不要试图手动按 BOOT 进下载模式** | 板上 BOOT 键已被改造成用户键，按它没用 |

## 2. 三种烧录方式（按推荐度排序）

### 方式 A：esptool 走 CH340K —— 推荐

```bat
D:\Espressif\python_env\Scripts\esptool.exe --chip esp32s3 -p COM8 -b 460800 ^
  write_flash 0x0 "G:\workbuddy\语音助手\dist\elder-companion.bin"
```

esptool 会通过 DTR/RTS 自动把芯片拉进 ROM 下载模式，**不需要按任何按键**。
若握手失败，先降速到 `115200` 重试一次。

### 方式 B：乐鑫官方 Flash Download Tool（图形界面，最省心）

1. 下载 <https://www.espressif.com.cn/en/support/download/other-tools>（Flash Download Tool）
2. 选 `chipType = ESP32-S3`，`workMode = develop`
3. 只填**一行**（用合并后的单 bin）：

   | 地址 | 文件 |
   | --- | --- |
   | `0x0` | `elder-companion.bin` |

4. `SPI SPEED = 80MHz`、`SPI MODE = DIO`、`FLASH SIZE = 16MB`，COM 选 CH340K 那个口
5. 点 `START`

### 方式 C：走板载 USB-JTAG（OpenOCD）—— 完全绕开串口

只有在前两种都不通时才用。WinUSB 驱动需要先被 Zadig 绑定到 `USB\VID_303A&PID_1001&MI_02`。

```bat
D:\Espressif\tools\openocd-esp32\v0.12.0-esp32-20250707\openocd-esp32\bin\openocd.exe ^
  -s D:\Espressif\tools\openocd-esp32\v0.12.0-esp32-20250707\openocd-esp32\share\openocd\scripts ^
  -f board/esp32s3-builtin.cfg ^
  -c "program_esp build/elder-companion.bin 0x10000 verify exit"
```

## 3. 常见失败与处理

| 现象 | 真实原因 | 处理 |
| --- | --- | --- |
| `A serial exception error occurred: Write timeout` | 芯片没进下载模式，App 占着 CDC 且不消费 OUT 端点 → `usbser.sys` 缓冲填满 | 换 CH340K 那个口（方式 A）；或拔插 USB |
| `Wrong boot mode detected (0xXX)!` | 同上 | 同上 |
| `Could not open COMx` | 端口号变了 / 设备被拔 | 重新枚举端口（见第 4 节） |
| `Failed to set baud rate 115200` | CH340 驱动异常或端口被占 | 换口；重插；任务管理器杀掉占用进程 |
| 集线器报 **Code 43 `CM_PROB_FAILED_POST_START`** | HUB 过流保护或线缆问题 | 换一根**数据线**、换一个**主板原生 USB 口**（别走显示器/键盘 Hub） |
| `Invalid head of packet (0x45)` | 收到的是 App 日志而不是 bootloader 应答 | 让 esptool 自己复位（默认行为），别用 `--before no_reset` |

## 4. 快速查当前端口号

```bat
:: 列出所有串口及其设备路径
reg query HKLM\HARDWARE\DEVICEMAP\SERIALCOMM
```

或用 PowerShell：

```powershell
Get-PnpDevice -PresentOnly | Where-Object { $_.FriendlyName -match 'COM\d+' } |
  Select-Object FriendlyName, Status, InstanceId
```

识别规则：
- **`VID_303A&PID_1001`** = ESP32-S3 原生 USB（COM 口，无自动下载）
- **`VID_1A86&PID_7522`** = CH340K = **烧录用这个**

## 5. 生成一个合并的固件镜像

### 5.1 【推荐】从 GitHub 下载已构建好的镜像

固件由 GitHub Actions 在 Espressif 官方容器里编译（本地不装 IDF 也能拿到成品）：

1. 打开仓库的 **Actions → firmware-build**，选最新一次 **绿色**的运行
2. 页面底部 **Artifacts** → 下载 `elder-firmware-esp32s3`（是个 zip，约 2.5 MB，解压后 6 个文件）
3. 解压出来**只需要烧这一个**：

   ```
   elder-firmware-esp32s3-merged-flash.bin
   ```

   从 `0x0` 直烧，命令：

   ```bat
   python -m esptool --chip esp32s3 --port COM3 write_flash 0x0 elder-firmware-esp32s3-merged-flash.bin
   ```

   > 该次运行的 job summary 里列出了每个文件的字节数和 SHA256 前 16 位，
   > 可以用它确认自己下对了文件。

其余 5 个文件（`bootloader.bin` / `partition-table.bin` / `ota_data_initial.bin` /
`xiaozhi.bin` / `generated_assets.bin`）是按 `flasher_args.json` 分地址烧写的**备选**，
日常不用管。`flasher_args.json` 里已经写好了每个文件该写到哪个地址，
用乐鑫 Flash Download Tool 时照它填即可。

> ⚠️ 早期版本的 CI 有一个 bug：`merge-bin` 因路径写错而失败，但被 `|| echo warning`
> 吞掉了，于是 job 显示绿色、summary 让下载一个**从未生成过的文件**。
> 已修（commit `05c70e3`）。如果你下载的 artifact 里**没有** merged 那个文件，
> 说明拿到的是旧构建 —— 回 Actions 里看该次运行的日志，确认 `merged-flash.bin = N 字节`
> 那一行存在再烧。

### 5.2 本地自行合并（本机装了 ESP-IDF 时）

```bat
python G:\workbuddy\语音助手\tools\make_firmware.py
```

输出：`G:\workbuddy\语音助手\dist\elder-companion.bin`
脚本会同时打印好完整的烧录命令。

## 6. 分区表（xiaozhi v2.0.5 用的 16MB 布局）

| Name | Type | SubType | Offset | Size |
| --- | --- | --- | --- | --- |
| nvs | data | nvs | 0x9000 | 16K |
| otadata | data | ota | 0xd000 | 8K |
| phy_init | data | phy | 0xf000 | 4K |
| ota_0 | app | ota_0 | 0x20000 | 4032K |
| ota_1 | app | ota_1 | 0x410000 | 4032K |
| assets | data | spiffs | 0x800000 | 8M |

> 8MB 的 `assets` 分区用于放形象图 / 表情 / 字体 / 提示音 —— 需求 4（2D 卡通形象）
> 和 R4（离线提示音）的资源都落在这里，容量足够。

**nvs 只有 16K，但放得下离线提醒**：整张 `elder_rmd_table_t`（16 条提醒）是
**877 字节**，只占分区的 5.4%，剩下 15.2K 留给 settings / WiFi 等。
所以「提醒时间存本地」在容量上没有风险。

> ⚠️ 这 16MB 里 `assets` 独占 8MB（`0x800000` 起），两个 app 槽合计 7.9MB。
> 这是**esp-sr MultiNet 离线语音识别没能启用**的直接原因 ——
> 没有多余的分区放模型文件，而现有的 `ota_1` 槽已经被双 OTA 占着。
> 详见 `docs/决策记录.md` D11。
