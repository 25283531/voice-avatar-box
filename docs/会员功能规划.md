# 会员功能规划（人工核销版）

> 适用场景：**暂时拿不到支付接口**，会员只能由平台管理端手动开通。
> 设计目标：让"用户付款 → 通知管理员 → 管理员肉眼核对收款 → 开通会员"这条链路可闭环、可对账、难出错。

---

## 1. 整体流程

```
┌──── 手机 APP ────┐        ┌──── 后端 ────┐        ┌──── 平台管理端 ────┐
│ 点击「开通会员」  │        │             │        │                    │
│ 选套餐            │──────▶ │ 创建订单    │        │                    │
│ 生成 4 位订单号   │        │ 分配随机金额│        │                    │
│                  │◀────── │ 返回金额+收款│        │                    │
│ 展示收款账号/二维码│        │             │        │                    │
│                  │        │             │        │                    │
│ 用户线下转账      │        │             │        │                    │
│ 点「我已支付」    │──────▶ │ 置为待核销  │──────▶ │ 待核销列表收到通知  │
│                  │        │             │        │ 输入订单号查询金额  │
│                  │        │             │        │ 核对自己的收款账号  │
│                  │        │             │◀────── │ 确认到账 → 开通会员│
│ 会员状态变为已开通│◀────── │ 开通会员    │        │                    │
└──────────────────┘        └─────────────┘        └────────────────────┘
```

## 2. 订单号规则

| 项 | 规则 |
| --- | --- |
| 长度 | **4 位** |
| 字符集 | `A-Z` + `0-9`（36 个字符） |
| 大小写 | **不区分大小写**，落库统一转大写，查询时也转大写 |
| 有效期 | **48 小时**，超时自动置为 `expired`，不再占用可用编码 |
| 唯一性 | **48 小时内不重复**（含所有状态的订单） |

### 为什么 4 位够用 + 必须服务端校验

36⁴ = 1,679,616 种组合。按生日悖论，约生成 **1500 个订单**后碰撞概率才到 50%。
本项目用户量级远小于此，但**必须做碰撞处理**，否则一旦撞号管理员就会核销错订单：

```
APP 生成 code → POST /api/membership/orders
                 ├─ 48h 内未占用 → 创建成功
                 └─ 已占用(409) → APP 重新生成再提交（最多重试 3 次）
```

APP 端生成必须用**安全随机**（不用 `Math.random()`），H5/小程序用
`crypto.getRandomValues()`，App 端用 `plus` 或降级到 `Math.random()` 并提示重试。

## 3. 金额区间随机（防重 + 可对账）

### 设计动机

管理员在收款账号里看到一笔**具体金额**的入账，就能反查到唯一订单。
所以金额必须在一段时间内唯一 —— 否则两笔 `50.00` 分不清是谁付的。

### 规则

| 项 | 规则 |
| --- | --- |
| 配置位置 | **平台管理端**（管理员设置，不写死在代码里） |
| 配置内容 | 区间 `[min, max]`，单位**分**（避免浮点误差） |
| 示例 | `1000 ~ 9999` 分 = `10.00 ~ 99.99` 元 |
| 生成 | 在区间内随机取一个整数分 |
| 唯一性 | **48 小时内不重复**（排除近 48h 已占用的金额） |
| 耗尽处理 | 区间可用值用完 → 拒绝创建并提示管理员**放宽区间** |

> 以 `1000~9999` 为例，48 小时内最多可承载 **9000 笔**订单，对本项目的量级完全够用。

### 边界情况

- 区间跨度太小（如 `1000~1005`）→ 很快耗尽，接口返回明确提示
- 管理员修改区间后，已存在的金额不受影响（只影响新订单）
- 过期（48h）订单占用的金额**释放**，可重新使用

## 4. 订单状态机

```
                  ┌──────────── 48h 超时 ────────────┐
                  ▼                                   │
  [创建] ──▶ pending ──▶ notified ──▶ confirmed ──▶ (终态)
              │            │             ▲
              │            └──▶ rejected │
              │                          │
              └──▶ cancelled(用户放弃)   │
                                         │
                          管理员点「确认到账」┘
```

| 状态 | 含义 | 谁触发 |
| --- | --- | --- |
| `pending` | 已创建，等待用户付款 | APP 创建订单 |
| `notified` | 用户声称已付款，等待管理员核对 | APP 点「我已支付」 |
| `confirmed` | 管理员确认到账，会员已开通 | 管理端 |
| `rejected` | 管理员未查到入账，驳回 | 管理端 |
| `cancelled` | 用户主动放弃 | APP |
| `expired` | 48 小时未支付 | 后端定时任务 |

> **只有 `pending` / `notified` 会占用订单号和金额**。
> `confirmed` / `rejected` / `expired` / `cancelled` 的号段在 48h 后释放。

## 5. "通知管理员"怎么做（无支付接口时）

按可实现程度排序，本项目**先做第 1、2 项**，第 3 项留配置位：

1. **管理端待办列表**（必做）：订单置为 `notified` 后进入「待核销订单」列表，
   管理员打开平台管理端即可看到，按创建时间倒序。
2. **订单号 + 金额醒目展示**（必做）：列表里直接显示
   `订单号 A3F9 · ￥57.30 · 用户 xxx · 12 分钟前`，管理员复制订单号即可。
3. **可选推送**（留 TODO，配置化）：管理端配置 webhook（钉钉 / 企业微信 / 飞书 / 邮件），
   订单 `notified` 时推送一条消息，内容包含**订单号**。未配置则静默跳过。

## 6. 管理员核销操作

```
管理端 → 会员核销 → 输入订单号 A3F9
   ↓
显示：订单号 / 金额 ￥57.30 / 提交时间 / 剩余有效期 / 关联用户 / 套餐（30 天）
   ↓
管理员打开自己的收款账号，核对是否有 ￥57.30 的入账
   ↓
┌── 有 ──▶ 点「确认到账」→ 会员立即开通，订单置 confirmed
└── 无 ──▶ 点「驳回」→ 订单置 rejected，可填备注（如"未查到该金额"）
```

- 核销是**幂等**的：重复确认同一订单不会重复加时长
- 每次核销写审计日志（谁、何时、订单号、金额）

### 后台直接分配（不走订单）

管理员也可以完全跳过支付流程，直接给用户开通会员：
`POST /api/admin/membership/grant { user_id, days, note }`
——用于亲友、测试账号、补偿等场景。

## 7. 会员 / 非会员的差异：陪聊时长

### 7.1 计量口径（关键）

> **一次「会话」= 从唤醒开始，到最后一句答复为止；空闲超过 90 秒自动切断对话。**

```
   唤醒            对话中...              最后一句答复       空闲 90s
    ├──────────────────────────────────────┤                 ├────▶ 会话结束
    │◀────────────── 计入配额的时长 ───────▶│
```

- 会话时长 = `最后一句答复时刻 − 唤醒时刻`（**不含**尾部 90 秒空闲）
- 每日配额 = 所有会话时长累加
- 空闲切断：连续 90 秒无有效输入 → 结束当前会话，不再计入时长

| | 非会员 | 会员 |
| --- | --- | --- |
| 每日陪聊总时长 | **3600 秒（1 小时）** | 不限 |
| 单次会话空闲切断 | 90 秒 | 90 秒（体验一致） |
| 服药提醒相关 AI 调用 | **不限** | 不限 |

### 7.2 服药提醒相关不占用配额

用户的原话例子：非会员说「**今天中午的降压药已经服用了**」——
即使当天 1 小时陪聊额度已用完，**仍要能调用 AI 做语义解析**（提取药品、时间、确认意图）。

判定为「服药/提醒类」的三种信号（任一命中即放行）：

1. **处于提醒确认窗口内**：设备刚播报完一条服药提醒，在确认窗口（默认 5 分钟）内
   的任何语音输入，都视为对该提醒的回应 → 放行
2. **命中服药关键词**（本地词表，由服务端下发、可配置）：
   `药 / 吃药 / 吃了 / 服了 / 服药 / 降压药 / 胶囊 / 片 / 提醒 / 日程 / 确认 等`
3. **明确的确认/取消意图词**：`好了 / 知道了 / 已完成 / 取消 / 稍后 等`

> 关键词匹配在**设备端本地**完成，不消耗任何 AI token。
> 未命中关键词且配额耗尽 → 走本地离线话术（"今天的聊天时间用完啦，明天再聊"）。

### 7.3 配额存储

- **设备端本地**统计并兜底（离线也能限流）
- 联网后通过 `/api/device/chat-usage` 上报明细，服务端按日对账
- 服务端在 `/api/device/sync` 时下发当日：`已用秒数 / 上限 / 空闲切断秒数 / 服药关键词表`

## 8. 数据模型（新增表）

| 表 | 作用 | 关键字段 |
| --- | --- | --- |
| `memberships` | 用户会员记录 | user_id, plan, started_at, expires_at, source, status |
| `membership_plans` | 套餐（定义开通天数与展示价） | code, name, days, price_cents, sort |
| `membership_orders` | 订单 | code(4位), user_id, plan_code, amount_cents, status, created_at, expires_at, notified_at, confirmed_at, admin_id, admin_note |
| `membership_amount_range` | 金额区间配置（单行） | min_cents, max_cents, enabled, updated_at |
| `chat_quota_config` | 陪聊配额配置（单行） | free_daily_seconds, idle_timeout_seconds, vip_unlimited |
| `chat_usage` | 每日陪聊时长 | device_id, date, used_seconds, session_count |
| `reminder_keywords` | 服药关键词表（下发设备） | word, enabled |

## 9. 接口清单

### 9.1 用户端（手机 APP）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/membership` | 会员状态、到期时间、权益、**当日陪聊已用/上限** |
| GET | `/api/membership/plans` | 套餐列表（天数 + 展示价） |
| POST | `/api/membership/orders` | 创建订单（body 带 4 位 code）；冲突返回 409 |
| GET | `/api/membership/orders/mine` | 我的订单列表 |
| POST | `/api/membership/orders/{code}/notify` | 我已付款，通知管理员 |
| POST | `/api/membership/orders/{code}/cancel` | 放弃订单 |
| GET | `/api/membership/payment-info` | 收款账号 / 二维码（管理端配置） |

### 9.2 管理端（平台）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/PATCH | `/api/admin/membership/config` | 金额区间、陪聊配额、收款信息 |
| GET | `/api/admin/membership/orders` | 订单列表（`?status=notified` 即待核销） |
| GET | `/api/admin/membership/orders/{code}` | **按订单号查询**（金额/用户/时间/套餐） |
| POST | `/api/admin/membership/orders/{code}/confirm` | 确认到账 → 开通会员（幂等） |
| POST | `/api/admin/membership/orders/{code}/reject` | 驳回 |
| POST | `/api/admin/membership/grant` | 后台直接给某用户开通 N 天 |
| POST | `/api/admin/membership/orders/expire` | 手动触发过期清理（也有定时任务） |

### 9.3 设备端

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/device/quota` | 当日配额（已用/上限/空闲切断/服药关键词表） |
| POST | `/api/device/chat-usage` | 上报一次会话时长（含是否 reminder 类） |

## 10. 安全与风控

- 订单创建频率限制：同一用户 60 秒内最多 3 次，避免刷号占满号段
- 订单号/金额占用只对 `pending`+`notified` 生效，过期自动释放
- 核销接口必须管理员权限（`is_admin`），并写审计日志
- 金额区间校验：`min < max`、`min >= 100`（至少 1 元）、`max <= 99999`
- 所有涉及金额的计算用**整数分**，禁止浮点
