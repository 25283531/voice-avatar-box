# 小爱触屏音箱 LX04 移植方案

> 目标：把「老人陪伴提醒助手」从 ESP32-S3 硬件移植到小米小爱触屏音箱 LX04，
> 让音箱开机直接进入我们的系统，保留音量键、中间键改作服药确认键，
> 灯效改为屏幕两侧竖向色带。

---

## 0. 一句话结论

**LX04 是 Android 设备（MTK MT8167A / Android 8.1 / 800×480 横屏），不是 ESP32。**
所以这不是「重编一份固件」，而是「写一个 Android App + 把系统换成最小集」。

> ⚠️ 本文写于 **2026-11-04 实机探测之前**，初版里的屏幕方向、色带像素、
> 中间键 KeyCode 都是调研推断，已被实机推翻。下文已就地更正，但**硬件事实的
> 唯一真源是 [`实机验证结果.md`](实机验证结果.md)**；两者冲突时以它为准，
> 并回来修本文，不要另立一份数字。

分两步走：

| 步骤 | 做什么 | 产出 |
| --- | --- | --- |
| **第一步（软件）** | 写我们的 Android 客户端：全屏 UI、左右色带灯效、按键拦截、AudioRecord 采集 + Opus + WebSocket 直连现有服务端 | 一个 APK，可在任何能装 APK 的 LX04 上跑起来 |
| **第二步（系统）** | 把 LX04 的 system 分区换成最小集，只留我们的 App，物理上移除小爱 | 开机即我们的系统，无法回到小爱 |

两步解耦：**第一步不依赖第二步**，可以先在官改固件（SP5/SP6）上验证全部功能；
确认无误后再做第二步换系统，那时 App 本身一行不用改。

## 1. 硬件真相（2026-11-04 实机更正版）

| 项 | 值 | 说明 |
| --- | --- | --- |
| SoC | **联发科 MT8167A**，4×Cortex-A35 | 不是 Amlogic；社区常见误传 |
| 内存/存储 | 1GB DDR3 / 4GB eMMC | 4GB 是通病，社区实测「装得下不到十个第三方 App」 |
| 屏幕 | 3.97" **800×480 横屏 / 240dpi / rotation=0** | ⚠️ 调研资料写的 480×800 竖屏**已被实机推翻**；5mm ≈ **47px** |
| 音频 | 双 MEMS 麦 (S2273) + ES7243 ADC + 1.5" 全频喇叭 | `stop mivpm` 后 `tinycap` 实测能录到真实声音 |
| 系统 | 国行出厂 **Android 8.1**（SDK 27，`userdebug` 可 root） | 32 位 **armeabi-v7a** 用户空间 |
| 顶部 | 3 个微动键 + 双麦 + 光线传感器 | 官方定义：音量- / 屏幕开关 / 音量+ |
| **灯光** | **没有任何物理 LED** | ⚠️ 顶部小板拆解确认。原 ESP32 版的 WS2812 灯带在 LX04 上不存在 |
| USB | **只供电不传数据** | 刷机需厂商改过的 USB gadget；本机已用 USB ADB + 网络 ADB 通了 |
| 电池 | 无 | 老人场景必须配 UPS |

### 1.1 由「无物理 LED」引出的灯效方案

原 ESP32 固件的灯效由 `firmware/components/elder/src/rgb.c` 驱动（WS2812B × 20，物理用 9 颗）。
LX04 上没有灯 ⇒ **灯效必须落在屏幕上**。

用户要求「屏幕两侧各留 5mm 宽的区域模仿状态灯」恰好就是正确解法：
色带只能画在屏幕上（实机确认四周没有物理黑边），按 240dpi 折算
`5 / 25.4 × 240 ≈ 47px`，中间内容区 `800 − 94 = 706px`：

```
┌──┬──────────────────────────────────────────────┬──┐
│▓▓│                                              │▓▓│  ← 左右各 47px 竖向色带（满高 480）
│▓▓│          主内容区（字幕/头像）706×480          │▓▓│
│▓▓│                                              │▓▓│
└──┴──────────────────────────────────────────────┴──┘
   47px                  706px                     47px
```

> 代码里**不写死 47**：`LedBandView` 用 `COMPLEX_UNIT_MM` 按运行时 density 折算，
> 换固件/换屏时「5mm」仍是 5mm。

**色带内渲染现有灯效语义**，与 `elder_rgb.h` 一一对应（优先级仲裁、感知亮度、gamma 2.2 查表全部沿用）：

| 原灯效 | Android 侧呈现 |
| --- | --- |
| 待机闪烁星光（TWINKLE） | 色带内逐段点亮、单色渐隐，2 秒一格 |
| 唤醒聆听（#00BFFF 55%） | 色带整体常亮深天蓝 |
| TTS 说话（#FF8C00 70%） | 色带整体常亮深橙 |
| 网络传输中（METEOR） | 一个亮头带拖尾沿色带纵向跑过 |
| 服药未确认（红闪） | 色带红色快闪 |
| 服药完成（天蓝闪 3 次） | 色带天蓝闪 3 次 |
| 按住渐变（天青由暗变亮） | 色带自下而上填充，**渐变本身是进度条** |

⚠️ **不使用系统状态栏**：色带会被状态栏/导航栏遮挡或被系统 UI 压住。
App 必须全屏（`FLAG_FULLSCREEN` + immersive sticky），自绘所有 UI。

### 1.2 顶部三键的映射

✅ **2026-11-04 实机已确认**，不再是推断：

| 物理键 | 原厂上报 | 现在的 Android KeyCode | 实现 |
| --- | --- | --- | --- |
| 音量+ | `KEY_VOLUMEUP` | `KEYCODE_VOLUME_UP` | `mtk-kpd.kl` 原样保留，App 不消费 |
| 音量- | `KEY_VOLUMEDOWN` | `KEYCODE_VOLUME_DOWN` | 同上 |
| **中间键** | **`KEY_POWER`(116)** | **`KEYCODE_F1`** | keylayout 重映射 + App 只认 F1 |

中间键实测就是 `KEY_POWER`，系统当场熄屏（logcat `Going to sleep due to power button`），
长按还会弹关机菜单 —— **应用层拦不住**，POWER 在 `interceptKeyBeforeQueueing`
阶段就被系统吃掉。解法是新建 `/system/usr/keylayout/mtk-pmic-keys.kl`：

```
key 114   VOLUME_DOWN
key 116   F1
```

重启后 `dumpsys input` 确认加载；连按 5 次实测 `getevent` 仍上报 116，
但 logcat 零熄屏、`mWakefulness=Awake`。详见 `实机验证结果.md` 第三节。

⚠️ `TopKeys.CONFIRM_KEY_CODES` 里**不许加回 `KEYCODE_POWER`**：触摸屏 event2/3
也声明了 POWER，双重触发会让老人按确认键时系统同时熄屏。

### 1.3 按键长按语义（1:1 复刻现有固件）

原 `elder_input.h` / `elder_rgb.h` 定义的行为全部保留：

- 提醒响铃期间短按 → 直接确认「已服药」
- 长按 ≥3s 后松开 → 30s 窗口内再短按 → 确认（不在响铃时也能用）
- 按住期间：色带渐变填充（天青 #00E5FF 由暗变亮），**渐变时长 = 3s，进度条同源**
- 松手判定：≥3s → 天蓝 #00BFFF 闪 3 次（成功）；<3s 且 >300ms → 粉红 #FF69B4 闪 5 次（失败）
- <300ms 的松手算机械抖动，**不闪失败**（原固件 2026-11-04 加的兜底，必须保留）
- 没有待确认提醒时按下 → **什么都不亮**（不欺骗老人）

## 2. 系统改造路线

### 2.1 分区表（来自 TWRP recovery.fstab，最权威）

```
A/B 双槽（只有这三个是双槽）：
  system_a / system_b    各 896 MB  ext4
  vendor_a  / vendor_b   各 256 MB  ext4
  boot_a    / boot_b     各  16 MB
单份：
  lk / lk2 (bootloader)   userdata ~1.04 GB
  nvram proinfo para seccfg tee1 tee2 kb dkb logo expdb odmdtbo_a/b
```

### 2.2 三条路线对比

| 路线 | 内容 | 工作量 | 风险 | 推荐 |
| --- | --- | --- | --- | --- |
| **C′** | Magisk root + 把 system_b 换成最小镜像（保留原厂 boot/vendor） | 1–3 周 | 中，可回滚 | ✅ **推荐** |
| **C** | LineageOS device tree + vendor blob 抽取 + 编译 ROM | 2–3 周 | 中高（SELinux/签名） | 备选 |
| **A** | 纯 AOSP + mainline 内核 | 3–6 人月 | 极高 | ❌ 不做 |

**为什么不走纯 AOSP**：AOSP 没有 `device/mediatek` 仓库；MT8167A 的 mainline 内核缺 panel/DSI、
触摸、codec、WiFi 驱动节点 —— 等于从零写四个驱动，且**没有任何成功先例**。

**为什么 C′ 可行**：`Project-Mico/device_xiaomi_mi_lx04` 是完整的 LineageOS device tree，
含 27 个 HIDL HAL 声明（含 `audio.primary.mt8167`、MTK codec service、WFO wifi offload）和
600 行 vendor blob 清单 —— **驱动不用写一行**。

### 2.3 C′ 的执行顺序（每步可回滚）

1. `mtkclient` 整盘备份 27 个分区 + 记录 GPT
2. seccfg 解锁（状态 1→3，社区已验证算法）
3. Magisk 打进 `boot_b`：`skip_initramfs\0` → `want_initramfs\0` **等长 patch**
   （保留原厂 verity 与加密）⚠️ 需补 busybox/magiskinit/magiskpolicy，
   否则报 `Magisk environment incomplete, abort`
4. 启动 root ADB（USB `0x0601`），确认 SELinux 状态（原厂 Enforcing）
5. 从原厂 system 提取必需物：
   - `/system/etc/permissions/` 下的 framework 权限 XML
   - 触摸 `*.kl`（⚠️ 原厂触摸是 **SWAP_XY + FLIP_Y** 翻转过的）
   - `audio_policy_configuration.xml` 在 **vendor**（不裁就安全）
6. 构造最小 system 镜像（我们的 APK + 精简 Launcher + 必要 framework 声明）→ 刷 `system_b`
7. 开机验证 → **成功后才写 `system_a`** → 最后统一写 boot
8. 视需要 factory reset 清掉 userdata 里小爱下载的语音包

⚠️ **不要用 `fastboot flash gpt_both0.bin`** —— LX04↔X04G 转换需要专门重写的 gpt 表，
刷错 gpt = 变砖。以 BROM/mtkclient 为主。

## 3. App 侧架构

复用现有服务端（`server/app/voice/`），**协议层一行不改**：

```
Android App
├── AudioRecord (16kHz mono)          ← 自建唤醒，不用小爱的
│   └── VAD + 唤醒词模型（sherpa-onnx / Porcupine）
├── Opus 编码 (JNI, armeabi-v7a)      ← ⚠️ abiFilters 必须锁 v7a
├── WebSocket → ws(s)://<地址>/api/voice/v1/ws
│   ├── JSON 帧：hello / listen / abort / stt / tts / llm ...
│   └── 二进制帧：Opus 音频（协议 v3）
├── 顶部按键 → dispatchKeyEvent
├── 左右 5mm(≈47px) 色带 → 移植 elder_rgb.c 的灯效引擎
└── 全屏 UI（禁用状态栏/导航栏）
```

服务端握手（`server/app/voice/session.py`）：

```json
{"type":"hello","transport":"websocket","session_id":"...",
 "audio_params":{"sample_rate":16000,"frame_duration":60}}
```

### 3.1 关键坑（移植前必须知道）

| 坑 | 说明 | 规避 |
| --- | --- | --- |
| **32 位用户空间** | 系统是 armeabi-v7a，arm64 的 libopus 会 crash | `ndk { abiFilters 'armeabi-v7a' }` |
| **SELinux Enforcing** | 原厂实测开启 | App 需签名对齐；Magisk 方案可 `setenforce 0` |
| **触摸 SWAP_XY + FLIP_Y** | 原厂触摸坐标翻转过 | 保留原厂触摸 HAL；App 内同时测 raw event 与 getevent 坐标 |
| **系统 UI 遮挡色带** | 状态栏/导航栏会压住色带 | 全屏 + immersive sticky，自绘所有 UI |
| **KEYCODE_POWER 长按关机** | ✅ 实机确认：中间键就是 POWER，应用层拦不住 | keylayout 重映射成 F1（已验证），App 只认 F1 |
| **麦克风独占** | ✅ 实机确认：`MiVpmService`(init 服务 `mivpm`) 常驻 16k 录音；**禁桌面不能释放** | 先 `stop mivpm`；永久禁用要改 `/vendor/etc/init/hw/init.project.rc` 或移走二进制 |
| **audio policy 采样率** | OEM 策略可能限制 mic 采样率 | 保留原厂 vendor（含 `audio_policy_configuration.xml`） |
| **4GB eMMC 寿命** | 频繁刷写加速损坏 | system 分区**写一次顶一次**，不要反复试错 |

- [x] `getevent` 抓到三个按键真实 KeyCode → 中间键 `KEY_POWER`，已重映射为 F1
- [x] `pm list packages` → 桌面 `com.xiaomi.micolauncher`，**语音无独立包**
- [x] `dumpsys media.audio_flinger` → `mivpm` 常驻占麦，`stop mivpm` 后释放
