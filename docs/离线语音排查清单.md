# 离线唤醒 / 离线命令词失效 —— 排查清单

> 2026-10-19 用户实测反馈：离线语音唤醒不能用、离线语音命令不能用。
> 本文给出**根因链**与**逐条排查步骤**，每条都写了「看什么日志」「期望看到什么」。

---

## 一、根因链（已在源码上逐行核对）

离线唤醒与离线命令词共用**同一份 MultiNet 模型包** `srmodels.bin`。
这条链上任何一环断了，两项功能会**同时**失效——所以只修一项必然复发。

```
CONFIG_USE_CUSTOM_WAKE_WORD=y + CONFIG_SR_MN_CN_MULTINET7_QUANT=y
        │
        ├─(1)→ scripts/build_default_assets.py 第 190 行 pack_models()
        │        扫 sdkconfig 里的 CONFIG_SR_MN_* 决定打进哪些模型
        │        ⚠️ 第 812 行原文：「Please select appropriate CONFIG_SR_MN_* options
        │           in menuconfig, or disable USE_CUSTOM_WAKE_WORD」
        │
        ├─(2)→ 打包产物写进 assets 分区（partitions/v2/16m.csv 的 assets 8MB）
        │        ⚠️ 只烧 app 分区 ⇒ 分区里没有 srmodels.bin
        │
        ├─(3)→ main/assets.cc 第 129 行读 config.json 的 "srmodels" 字段
        │        ├─ GetAssetData() 失败 ⇒ 「The srmodels file %s is not found」
        │        └─ srmodel_load() 失败 ⇒ 「Failed to load srmodels.bin」
        │        ⇒ models_list_ 保持 nullptr
        │
        ├─(4)→ audio_service.cc 第 656 行 SetModelsList()
        │        esp_srmodel_filter(ESP_MN_PREFIX) == nullptr
        │        ⇒ 不设 CustomWakeWord
        │
        └─(5)→ audio_service.cc 第 463 行 wake_word_->Initialize(codec_, nullptr)
                 ⇒ ESP_LOGE "Failed to initialize wake word"
                 ⇒ 离线唤醒与离线命令词**双双不可用**
```

**已核实为正确、无需改动的部分**：

| 项 | 现状 | 结论 |
| --- | --- | --- |
| 分区表 `partitions/v2/16m.csv` | assets 分区 8MB 存在 | ✅ 够装（模型 2.68MB） |
| `CONFIG_PARTITION_TABLE_CUSTOM_FILENAME` | 指向 `partitions/v2/16m.csv` | ✅ |
| `CONFIG_SR_MN_CN_MULTINET7_QUANT` | 已在 sdkconfig overlay 里 | ✅ |
| 唤醒词拼音/汉字 | `ni hao xiao nuan` / `你好，小暖` | ✅（2026-10-18 已改） |

⇒ **最可能的两条**：① 烧录方式（只刷了 app，没刷 assets 分区）；
② 编译前没清 `build/`，`sdkconfig.h` 里残留第三方/旧配置导致模型没被打包。

## 二、排查步骤（按顺序做，每步都有明确的判据）

### 第 1 步：确认烧录的是**整包**，不是只烧 app

**这是最常见的原因，且症状与「模型没打进去」完全一样。**

- ❌ 错：用 `idf.py app-flash` 或只烧 `firmware/xiaozhi/build/xiaozhi.bin`
- ✅ 对：烧 **`merged-flash.bin`**（含 app + assets + nvs 等所有分区）

本项目在 HBuilderX 里打包 APP 时会自动合并；如果你手工烧录，用
`build/merged-flash.bin`，并按 `build/flash_args` 里的偏移烧。

**判据**：烧完后设备首次开机，串口**不应该**出现
`E (xxxx) Assets: The srmodels file srmodels.bin is not found`。

### 第 2 步：编译前清干净 build 目录

`firmware/xiaozhi/sdkconfig.h` 不入库，可能是上一次编译（甚至上一次同步别的板型）
留下的残留配置。**必须在 `firmware/xiaozhi/` 目录下**执行：

```bash
rm -rf firmware/xiaozhi/build
# 然后重新全量编译（不要用 --incremental）
```

**为什么必须清**：模型打包脚本读的是 `sdkconfig.defaults` 合并后的结果，
而 kconfig 的增量更新在新旧默认值冲突时**以后者为先**，残留值会让
`CONFIG_SR_MN_CN_MULTINET7_QUANT` 实际未生效。

### 第 3 步：把开机串口日志发我（**最关键**）

请把**从上电到出现表情**这一段的完整串口日志发我（波特率 115200）。
我需要以下四类行来精确定位断在链条的哪一环：

| 序号 | 日志关键词 | 出现即代表 | 缺失即代表 |
| --- | --- | --- | --- |
| ① | `CustomWakeWord` 附近的 `Add command:` 列表 | 唤醒词已注册进 MultiNet | ❌ 链路断在 (1)(2) |
| ② | `elder 离线命令词已预置 N 条` | elder 词表在（我方代码） | 我方代码没跑到 |
| ③ | `Assets: The srmodels file ... is not found` | ❗ assets 分区缺文件 | 见第 4 类 |
| ④ | `Assets: Failed to load srmodels.bin` | ❗ 文件在但解析失败 | 见第 5 类 |
| ⑤ | `AudioService: Failed to initialize wake word` | ❗ 模型列表为空 | 链路上游必然有问题 |

**快速自判**：
- 看到 ③ 或 ④ → **模型没进分区或没打包**，回第 1、2 步。
- 三条都没有（③ ④ ⑤ 都没）→ 链路上游是好的，请把日志给我，我继续往下查。
- 有 ⑤ 没有 ③ ④ → 可能是 `esp_srmodel_filter` 的前缀不匹配，需要看 `models_list_`
  实际内容。

### 第 4 步：确认模型真的被打包了（本地就能查，不用等日志）

编译完成后，直接看打包产物里有没有模型：

```bash
# 确认 assets 分区镜像存在且非空
ls -la firmware/xiaozhi/build/assets.bin      # 或 assets_image.bin
# 确认 srmodels.bin 确实生成了
find firmware/xiaozhi/build -name "srmodels.bin" -exec ls -la {} \;
```

若 `srmodels.bin` **不存在**，就是 sdkconfig 没生效——回第 2 步；
若存在但 `assets.bin` 很小（< 3MB），说明模型没被并进去。

## 三、离线命令词的额外说明

我们的 6 条离线命令词（`elder_cmd_words.h`）走的是**同一个 MultiNet 模型**，
所以第 1~3 步对它们**同样适用**。区别只在于：

- 唤醒词匹配失败 ⇒ 只是没唤醒
- 命令词匹配失败 ⇒ 语音没反应，但**按键兜底仍然可用**
  （长按后 30 秒内短按一次确认，见 README）

⇒ 如果离线命令词失效但按键能用，说明 elder 侧逻辑正常，问题确实在模型侧。
