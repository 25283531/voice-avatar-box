## 2. 缓存策略（这是本模块的核心，不是可调参数）

```
老人说「平顶山天气」
  ↓
geo 缓存命中？ ──否──→ 调 GeoAPI（城市名 → 经纬度）──→ 存 geo 缓存（30 天）
  ↓ 是
天气缓存命中？ ──是──→ 直接返回（**0 次上游调用**）
  ↓ 否
调和风 → 存缓存（TTL 60 分钟）→ 返回
```

**关键性质：**

1. **不拉全国。** 只有真被问过的城市才进表。冷门城市没人问，就永远不产生调用。
2. **60 分钟内重复问，不消耗 API 次数。** 这是唯一真正省钱的机制。
3. **过期行不删**（只不再命中）。它是「需求记录」，预热任务靠 `last_hit_at` /
   `hits` 判断该续谁。到点就删的话，「按需预热」会退化成「每次冷启动」。
4. **上游挂了用旧数据兜底**，返回里 `stale=true`。对老人来说「一小时前的温度」
   远好于「查不到天气」；但**不假装新鲜**，后台能看到降级。
5. **预热只刷最近 24 小时被问过、且 10 分钟内要过期的城市**，每 10 分钟一轮。
   预热**不产生 geo 调用**（后台行为不该新增任何"查找"类调用），坐标没了就跳过。

## 3. 环境变量全表

| 变量 | 默认 | 说明 |
|---|---|---|
| `ELDER_QWEATHER_HOST` | 空 | API Host，不带 `https://`（带了会自动收敛） |
| `ELDER_QWEATHER_PROJECT_ID` | 空 | JWT 的 `sub` |
| `ELDER_QWEATHER_KEY_ID` | 空 | JWT header 的 `kid` |
| `ELDER_QWEATHER_DEVELOPER_ID` | 空 | JWT 的 `iss` |
| `ELDER_QWEATHER_PRIVATE_KEY` | 空 | 私钥 PEM 全文（优先） |
| `ELDER_QWEATHER_PRIVATE_KEY_PATH` | 仓库父目录同名文件 | 私钥路径 |
| `ELDER_WEATHER_TTL_MIN` | `60` | 天气缓存有效期（分钟） |
| `ELDER_WEATHER_GEO_TTL_DAYS` | `30` | 城市坐标缓存（天） |
| `ELDER_WEATHER_DEFAULT_CITY` | `平顶山` | 老人没说城市时用 |
| `ELDER_WEATHER_TIMEOUT_SEC` | `6` | 单次上游超时 |
| `ELDER_WEATHER_WARM_HOURS` | `24` | 预热只看最近 N 小时被问过的城市 |
| `ELDER_WEATHER_WARM_AHEAD_MIN` | `10` | 缓存剩 N 分钟就提前续 |
| `ELDER_WEATHER_ENABLE` | `1` | 总开关 |

> `ELDER_WEATHER_TTL_MIN` 写错（非数字或 ≤0）会**回落 60 而不是变成 0**。
> TTL=0 意味着永不命中缓存 —— 功能上完全看不出来，只有账单会说话。

## 4. 怎么验证真的在工作

### 4.1 看配置是否齐

```bash
curl -s -H "Authorization: Bearer <用户token>" http://localhost:8080/api/weather/status
```

返回 `configured: true` 才算配好；`missing` 会列出还缺哪个变量。

### 4.2 看缓存是否命中（省钱证据）

```bash
# 第一次：source=api（真的调了和风）
curl -s -H "Authorization: Bearer <token>" "http://localhost:8080/api/weather/now?city=平顶山"
# 第二次：source=cache（0 次上游调用）
curl -s -H "Authorization: Bearer <token>" "http://localhost:8080/api/weather/now?city=平顶山"
```

### 4.3 看语音链路

对设备说「小智，今天天气怎么样」→ 日志里应出现
`elder.weather` 的缓存命中 debug，且 LLM 会调用 `get_weather` 工具。

### 4.4 自动化测试

```bash
python tools/test_weather.py     # 93 条断言，含"问 11 次只调 1 次上游"
```

## 5. 数据库

新增一张表 `weather_cache`（`Base.metadata.create_all` 自动建，无需迁移脚本）：

| 列 | 说明 |
|---|---|
| `cache_key` | `now:101180101` / `daily:101180101:3` / `geo:平顶山` |
| `city_name` | 归一化后的城市名 |
| `payload` | **上游原始 JSON**（不是口语化结果 —— 改文案不用清缓存） |
| `fetched_at` / `expires_at` | 抓取与过期时刻 |
| `last_hit_at` / `hits` | 预热筛选依据；预热刷新**不**计入 hits |

超过 7 天没人问的行由预热任务顺带清理（`cache.purge_stale`）。

## 6. 已知限制

1. **首次问一个新城市要两次往返**（geo + 天气）。第二次开始才只有一次。
   想彻底消掉这两次，只能提前预热该城市 —— 但那违背「不拉全国」。
2. **老人说「俺们这儿」这种指代**，靠 LLM 从上下文补城市名；补不出来时
   会反问「您说的是哪个城市」。不做别名表（"帝都→北京"写不完，写几条反而
   给人"已经处理过了"的错觉）。
3. **和风免费额度**：具体次数看你的套餐。`/api/weather/status` 的 `total_hits`
   能看出缓存省了多少次。
